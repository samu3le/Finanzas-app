# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal, single-user, offline-first finance tracker: desktop web + installable PWA. Payments in COP/VES, reporting in USD, shared-expense "activities" (participants, payer, splits, pairwise debts, settlements). UI copy is in Spanish.

## Commands

```bash
npm run dev          # Vite dev server
npm run build        # tsc -b + vite build (also generates the service worker)
npm run preview      # serve the build; use it to test PWA install/offline
npm run typecheck    # tsc -b
npm run lint         # oxlint (.oxlintrc.json)
npm test             # vitest run (src/**/*.test.ts, node env)
npx vitest run src/domain/money.test.ts   # single file
npx vitest run -t "name"                  # single test by name
```

Supabase env vars (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`) go in `.env.local`; only needed once sync is wired.

## Architecture

- **Dexie (IndexedDB) is the local source of truth.** Schema in `src/db/db.ts` (`FinanzasDb`), row types in `src/db/types.ts`. Screens read with `useLiveQuery` from `dexie-react-hooks`. Changing indexes requires a new `this.version(n)`, never editing version 1 in place.
- **Sync model (planned, phase 4):** every synced row extends `SyncedEntity` (UUIDv7 `id`, `createdAt/updatedAt`, soft delete via `deletedAt`, `serverSeq` null until server acks). Local writes enqueue into the `outbox` table; `meta` holds sync cursors. `exchangeRates` is server-written and read-only on the client (rates are fetched server-side by a Supabase Edge Function on cron, not from the browser). `src/lib/supabase.ts` creates the client lazily so the app works offline / without env vars.
- **Money:** amounts are integer minor units (`*Minor` fields), rates are decimal strings handled with `big.js` — never use JS floats for money. `src/domain/money.ts` is pure logic: `resolveAmounts` takes what the user typed (`entryMode` `usd` or `native`, that side is exact) and derives the other side from `fxRate` (units of paid currency per 1 USD). Allowed rate sources per currency are in `RATE_SOURCES_BY_CURRENCY` (COP: `trm`; VES: `bcv_usd`, `bcv_eur`, `binance_usdt`, manual `p2p`). Each money row stores the full `ConvertedAmount` snapshot (both amounts, source, rate) so history never gets re-converted.
- **Activities:** balances are computed pairwise from `activityExpenses` + `expenseSplits` (`shareUsdMinor`) + `settlements`; `computePairwiseBalances` is not written yet (phase 3).
- **Routing:** TanStack Router file routes in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin (don't edit, it's lint-ignored). `__root.tsx` holds the layout: bottom nav on phones, sidebar from 768px.
- **UI:** shared components are grouped by file, not one-per-file: `components/form.tsx` (inputs, `MoneyInput`), `components/ui.tsx` (Accordion, Dialog, EmptyState, …), `components/charts.tsx` (hand-rolled SVG charts, each with a table view). `/design` (`routes/design.tsx`) is the living style guide — add new components there.
- **Theming:** Tailwind v4 with CSS tokens in `src/index.css` (`--bg`, `--surface`, `--accent`, `--series-1..5`, …), light/dark via `prefers-color-scheme` overridden by `data-theme` on `<html>`. Theme colors are duplicated in `src/lib/theme.ts`, the `theme-color` metas in `index.html` and the PWA manifest in `vite.config.ts`; keep them in sync. Chart series colors are a fixed, validated order: don't cycle, fold extras into "Otros".
- `@/` aliases `src/`.
